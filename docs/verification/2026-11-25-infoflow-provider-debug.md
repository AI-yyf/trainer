# Trainer 信息流与模型配置排障记录

日期：2026-11-25。产品依据：`.trainer-convergence/product-contract.md` v2.1。

本轮从真实使用动作追踪到持久化与回写边界，重点是配置串线、异步结果过期、消息丢失和错误归因。修复均保留工作区原有未提交改动；此前已有的 FSRS 与消息样式工作不计为本轮新增修复。

## 已确认的根因与修复

| 问题 | 触发与后果 | 修复边界 |
| --- | --- | --- |
| 不同连接的模型目录混用 | 选择连接 B 时，仍用 A 的列表校验模型，并把 A 的目录写进 B | 校验、模型目录和额度元数据只使用目标连接的身份 |
| 未激活的已保存连接无法选中 | 没有活动 profile 时，选择一个已有连接被提前当成“已经激活” | 按实际 profile 身份激活，再保存模型 |
| 模型切换与思考强度并发覆盖 | 后一个操作读取前一个操作提交前的模型，最终丢失思考配置或回写旧模型 | 保存、模型切换、思考调整共享同一执行队列；读取基线也在队列内 |
| 保存失败后配置与密钥不一致 | profile 已更新，随后配置保存失败；只回滚密钥使 profile 指向已删除的引用 | 一起恢复原 profile、已写配置及密钥；注册表读取返回独立快照；配置写入串行执行 |
| 密钥存储短暂故障造成凭据丢失 | 无法读取旧密钥被当成“没有旧密钥”，新配置写入后清理了旧引用 | 对暂时性读取失败终止保存，保留原配置及凭据 |
| 传输身份被错误折叠大小写 | 不同 URL 路径、模型 ID、SecretStorage 引用命中同一个缓存；服务端也误认探针结果 | 仅规范化 URL 的主机部分，保留路径、模型和密钥引用的大小写；同步修复服务端与宿主显示适配 |
| 旧连接检查覆盖当前状态 | 检查期间切模型、切工作区，或发起新检查，旧结果仍写入当前视图 | 回写前核对工作区、连接、模型、密钥和检查先后顺序；过期结果不应用 |
| 旧对话结果污染新连接 | A 请求返回失败时从当前 store 取 B，错误地把 B 标记为失败；旧成功也可能清除新错误 | 请求携带自身配置与密钥身份，失败记录和成功恢复均核对当前身份 |
| 保存后重复发送配置快照 | 本地保存已应用，异步尾部再次发送同一快照，增加表单被旧数据覆盖的机会 | 保存只应用一次快照，尾部仅确认本地保存结果 |
| 否定、询问和示例被当成操作 | “不要生成练习”“如何修改计划”、引用或代码里的命令触发了动作 | 解析学习者的操作语句，排除否定、询问、引用和代码；明确保存请求进入计划确认流程 |
| 排队消息使用了错误文本 | 出队时复用当前草稿分析，原问题变成默认提示或新草稿；技能附件也取错来源 | 每次分析实际提交的文本与附件，保留后来尚未发送的草稿 |
| 排队确认与顺序失效 | 原草稿已清空，点击确认无法执行；后续消息越过等待确认的操作 | 确认保留原提交；确认期间暂停队列；按会话身份隔离队列 |
| 首次对话被准入流程拦截 | 普通提问被迫先绑定项目；首次绑定完成后，计划请求又被降为普通对话 | 普通只读对话可直接发送；资产写入仍先绑定；绑定后重新解析原操作并保留确认边界 |
| 刷新跳回会话底部 | 阅读位置恢复与自动跟随同时控制滚动 | 恢复已保存位置期间，自动跟随让出控制权；新发起回合仍保持可见 |
