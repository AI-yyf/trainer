# Trainer Codex Prompt

> 历史阶段说明：本文属于早期三视图收束阶段，不再代表当前顶层 IA。
> 当前 Trainer 顶层契约请以 [docs/ui-contract.md](../ui-contract.md) 为准：`Coach / Plan / Resources / Training / Settings`。

请按 `docs/plans` 中的 trainer coach-first 文档，持续实现并打磨这个项目，不要停留在建议层。

目标只有一个：把 Trainer 做成一个长期代码教练插件。它不是 AI 仪表盘，而是极简、强大、像 Codex 一样自然的侧边栏教练。

硬性要求：
- 顶层只保留 `对话 / 计划 / 设置`
- `研究` 不是独立页面，而是教练在消息流里的后台能力
- UI 必须极简、凝练、低 AI 味、贴合 VS Code、信息密度高但易懂
- 功能强大来自后端教练能力，不来自前端堆入口
- 核心能力必须覆盖：idea 实现引导、基于现有项目提炼训练题、改造已完成项目、原理讲解、长期记忆、复习节奏、情绪支持

执行要求：
- 直接实现，不空谈
- 先做高价值主链路，再补细节
- 每次修改后都同步收敛布局、交互、文案、层级和字体
- 优先复用现有能力，不造多余轮子
- 完成代码、联调、构建检查，并明确下一步

一句话原则：
让用户把想法发给教练，教练就能理解项目、研究方案、拆解计划、持续记忆、引导编码，并始终通过一个高级、安静、好用的侧边栏完成这一切。
