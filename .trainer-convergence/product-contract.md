## 1. Trainer 是什么

Trainer 是一个**记得你、守在你项目里、只认你亲手做到的事**的技术教练（从编程起步）。

- 它的目标不是替你写代码，而是让你最终能自己写。
- 它不是代码 agent，不是学习管理后台，也不是通用聊天客户端。

## 2. 北极星

> **这周你比上周多了哪些能独立做到的事，而且有证据。**

由此推出三条规则：

1. 一段学习对话应当至少留下一样东西：**一次尝试**、**一条证据**或**一个约好的复习**。三样都没有，就是没有产出的对话（直接问答模式除外）。
2. 教练说得越少越好，你动手的时间越多越好。
3. 任何界面上的进度表达，都必须能追溯到一条证据。

## 3. 用户可见的概念只有四个

| 概念 | 用户的问题 | 内部承载（不出现在 UI 文案里） |
|---|---|---|
| **目标** | 我在学什么、下一步是什么 | 长期计划、阶段、微目标、修订号、变更提议、Goal mode 计时器 |
| **练习** | 现在动手 | 即时练习、候选卡、正式卡、FSRS、复习队列、训练卡库 |
| **掌握进度** | 我真的会了吗 | 证据账本、四维投影、档位、失效、信任级别 |
| **资料** | 依据在哪 | 规范 Markdown、配套提取图片、Research Brief、版本、引用 |

- 任何新 UI 文案只能使用正式、克制的自然语言，严禁泄漏内部系统术语（候选卡、入库、确认入库、训练卡库、账本、投影、修订号、到期队列、后续和回看、UI proxy 等）。
- **同一个事实只说一次**：复习统一叫"今天要复习 N 个"，不再并列"待回顾"和"到期练习"。

## 4. 形态与唯一输入框主权（Single-Composer Sovereignty）

- **两个一级目的地**：对话、资料。历史和设置是工具入口。
- **只有一条会话与一个唯一输入框**：所有学习活动、作答、追问、要提示、提交反思、查询细粒度学习真相（完整阶段路线、已完成阶段、某项掌握度的具体证据记录、复习依据）、调整学习计划、围绕资料提问与生成讲稿，**全部通过底部唯一 `CoachComposer` 输入框完成**。
- **学习是对话的记忆，不是去处**：
  - 对话顶部一行：目标 · 当前一步 · 今天要复习的数量；
  - 练习以一张克制、**可折叠**的「当前动作/验证卡」出现在对话流底部，**不渲染第二作答输入框，也不在主对话流中渲染卡片库 CRUD 管理表单**；真实验证通过卡片上的宿主验证按钮或对话指令完成，作答与反思均从底部唯一输入框提交；
  - 进度以**一句人话**出现在对话流里（例如"已独立完成 2 次：识别重复写入"），具体证据细节可通过输入框向教练直接询问；
  - 学习抽屉只作为**纯只读一页备忘**（当前目标、到期练习、单一 4 段正式能力条），不放调整表单与管理按钮；Goal mode 与正式学习目标归一到同一套服务端目标真相；
  - 资料页顶部只做极简的本地文件名筛选，底部唯一输入框明确用于围绕当前/所选资料提问或生成状态流讲稿；资料入库默认规范化为 `.md` + 提取图片 `assets/<id>/*.png`，点击 `.md` 资料默认以 VS Code Markdown 图文预览打开，源码编辑退为次要入口；
  - **零拦截冷启动**：新打开任意代码项目时，允许先直接通过输入框对话；仅在首次需要落盘笔记、资料或建立长期计划时温和引导或一键绑定 `<LibraryRoot>`，代码工程目录始终保持零污染。
- **每张卡最多一个主动作**；每条回复的常驻动作不超过 3 个，其余收进"更多"。
- 旧路由 `plan / training / progress` 保留为兼容别名，统一落到对话 + 对应位置。

## 5. 教学（RethinkFun 状态流理论重建内核）

- **状态驱动，而不是概念清单**：默认沿 `当前状态（已知 / 未知 / 目标 / 障碍） → 旧做法失败（缺口） → 需求逼出新对象（构造概念，而非先定义再解释） → 变量先于公式（来源/角色/缺失后果） → 约束自然推出公式或设计 → 代码作为理论对象的实现状态并回指理论 → 真实环境校验 → 每 2–3 个对象做一次认知回收` 推进。
- **命题推进与零废话纪律**：每句话只完成现象 / 问题 / 原因 / 推理 / 结论之一；禁用空话垫词（如"大家都知道 / 显然 / 其实很简单 / 换句话说 / 接下来我们来看一下 / 非常巧妙 / 希望对你有帮助"），禁止暴露内部工具与系统流水账。
- **双速自适应（同一内核，不同颗粒度）**：
  - **快节奏动手引导（默认）**：先给 1 个最小可验证动作或直指缺口的反问，等学习者尝试后纠正一个误解，再约好下一次复查；
  - **深度讲透模式（"讲明白 X" / 原理推导 / 资料精读）**：完整走通旧方案失败 → 最小直觉图景 → 变量与对象构造 → 3–5 步消缺口推导（严禁"代入即得"）→ 代码回指理论（含不变量与失败点）→ 对比对象 + 边界/失败点 + 最小可运行例子 + 认知回收，并支持沉淀为 `<LibraryRoot>/Trainer Library/` 下的规范 `.md` 讲稿；
  - **推理型复习（FSRS）**：检验"即使忘了公式或套路，能否从约束重新推出来"，而非机械背诵。
- **学习者说了算**：明确要求"直接告诉我"时就直接讲，讲完不强拉进练习，最多轻提一句"要不要变成一个小练习"。卡住时先帮你脱困，再谈练习。
- **用你的项目当教材**：练习和例子优先来自学习者真实的代码、报错和环境；验证跑在真实环境里（包括远程）。
- **先备课再教**：对重要目标遵循 研究 → 备课 → 教学 → 验证；明确区分"有来源的结论 / 模型推断 / 未验证"。
- **节奏就是教学法**：
  - 首个可见内容 ≤ 2 秒（一句反问、一个动作，或极简真实进度"正在查看 `xxx.py`"）；
  - 短回合完整回复 ≤ 6 秒；
  - 深度讲解可以随后流式补充，但不得阻塞第一步。

## 6. 证据（不可退让）

- 自称"会了"不等于验证过；一次通过不等于长期掌握；AI 帮你做出来不等于你独立会做。
- 客户端提交的证据一律是 `self_reported`；只有宿主验证路径（`/training/verification/attest`）能证明可执行能力。
- 文件 hash 变化时，旧证据失效；删除来源时，引用会被标记。
- 结果未知（中断、超时、断线）时**不写证据**。
- 能力展示**禁止百分比和分数**，档位必须与服务端投影的状态**一一对应**，不得丢档。

## 7. 主动性

- 教练可以主动出现，但要有预算，宁少勿多：
  - 碰到与薄弱项相关的报错时，轻提一句，邀请学习者先自己定位；
  - 复习安排在工作间隙，不打断正在写代码的人。
- 任何计划变更只能是**提议**，必须展示原因并得到学习者确认。

## 8. 硬边界

- Coach 只讲解、分析、引导、验证，**从不编写或修改学习者的项目代码**；不向 Coach 注册写工具。
- 不做 Coach / Pair / Agent 三种执行模式，不做多 agent 和自主编码。
- Local Brain + Remote Hands：身份、记忆、计划、证据留在本地；远程只做读、搜索、hash、诊断、验证；凭据永远只在本地。
- destructive 操作（只针对 Trainer 自有资产）需要明确授权，并留有回收站、checkpoint 和 ledger 记录。

## 9. 不做

- 不新增一级目的地或独立的学习、训练、成长页面。
- 不做仪表盘、课程表，不让卡片库管理界面成为主角。
- 不做假完成态、假百分比、假分数。
- 浏览器端只做**捕获**（popup 快速捕获 + 右键菜单）。侧栏对话客户端已冻结：保留现有代码与测试，不再扩展，也不作为产品入口宣传。
- 不新增只证明形状、不证明行为的源码文本守卫测试。

## 10. 总验收：一条故事

> 周一学习者说"我想真正搞懂幂等"。教练读了项目，指出 `retry()` 的重复写入，先让学习者说出自己的理解，再让他自己改。改完后，教练在真实环境里验证通过，记下一条**独立完成**的证据。
> 周四，学习者在另一个模块遇到类似问题，教练只提醒了一句，学习者自己修好了，记下**迁移**。
> 两周后复查，学习者仍能讲清为什么。
> 全程学习者没有打开抽屉，也没有看到任何看不懂的词。

**通过条件**：用**真实模型**、在安装态 VSIX 中、同一份数据里，把这条故事从头跑到尾（时间用受控时钟推进），并完成一次**人工教学质量签核**。在此之前，任何"完成"声明都只是切片证明。
